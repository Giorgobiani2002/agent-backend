# დღგ-ის აღრიცხვის პრაქტიკული მოდული

ეს არის Declario-ს ორიგინალური სასწავლო მოდული. იურიდიული დასკვნის წყაროა საქართველოს მოქმედი საგადასახადო კოდექსი და ფინანსთა მინისტრის ბრძანება №996.

## გაყიდვის და შესყიდვის მხარე

დღგ-ის აღრიცხვამ ცალ-ცალკე უნდა შეინახოს:

- დასაბეგრი ოპერაციის თარიღი;
- დასაბეგრი ბაზა;
- დარიცხული output VAT;
- მიღებული input VAT;
- დოკუმენტის სტატუსი;
- გათავისუფლების ან ნულოვანი განაკვეთის საფუძველი;
- მომწოდებლისა და მყიდველის საიდენტიფიკაციო მონაცემები.

წიგნში მოცემული ზოგადი მაგალითი ვერ შეცვლის მიმდინარე სამართლებრივ ნორმას. თუ შესაბამისი კანონის წყარო retrieval-ში არ არის, ჩატმა უნდა თქვას, რომ სამართლებრივი დადასტურება აკლია.

## პერიოდის პროექტი

დეკლარაციის draft უნდა შეიქმნას მხოლოდ სინქრონიზებული და შესაბამის პერიოდში მოხვედრილი დოკუმენტებიდან. შედეგი უნდა აჩვენებდეს:

- გაყიდვების რაოდენობას და დასაბეგრ თანხას;
- output VAT-ს;
- დასაშვები შესყიდვების რაოდენობას და თანხას;
- input VAT-ს;
- net გადასახდელს ან ჩასათვლელ ნაშთს;
- გამოტოვებულ, უარყოფილ ან საეჭვო დოკუმენტებს.

## კონტროლის საკითხები

- ოპერაციის თარიღი არ უნდა ჩანაცვლდეს ფაილის ატვირთვის თარიღით.
- input VAT არ უნდა ჩაითვალოს მხოლოდ იმიტომ, რომ PDF არსებობს.
- დაბრუნება და კორექტირება უნდა უკავშირდებოდეს თავდაპირველ დოკუმენტს.
- გათავისუფლებული და ნულოვანი განაკვეთის ოპერაციები ერთმანეთში არ უნდა აირიოს.
- უცხოურ ვალუტაში ოპერაციას სჭირდება შესაბამისი კურსი და თარიღი.
- ხელით შეტანილი კორექტირება ცალკე უნდა გამოჩნდეს.

## გაგზავნის უსაფრთხოება

Draft-ის შექმნა შექცევადი მოქმედებაა. საბოლოო გაგზავნა საჭიროებს ზუსტ preview-ს და მომხმარებლის approval-ს. approval-ის შემდეგაც უნდა შემოწმდეს, რომ მონაცემების hash არ შეცვლილა.
